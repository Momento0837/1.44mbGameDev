# 1.44MB Game Dev

외부 이미지나 게임 엔진 없이 Windows GDI로 그리는 소형 C++ 게임 프로젝트입니다.

현재 화면 구성:

- 기본 클라이언트 크기: 800 x 600
- 중앙 플레이 영역: 400 x 400
- 플레이 영역 바깥: 검정 레터박스
- 장면: 하늘, 유리창, 벽, 제작대, 재료통, 체크 바닥, 보도 경계, 도로 순으로 구성
- 바닥: `#A8CBA9`, `#F2FBF1`을 사용한 깊이 3칸의 1점 투시 체크 격자
- 바닥 가로 폭: 시작선은 플레이 영역 전체를 채우고 하단에서 112%까지 완만하게 확장
- 바닥 세로 배율: `kFloorHeightScale` 값으로 시작 위치를 유지한 채 조절
- 바닥 안티앨리어싱: 3배 해상도 슈퍼샘플링 후 고품질 축소
- 기본 소실점: 플레이 영역 정중앙 `(200, 200)`
- 상단 암막: 장면과 레터박스 위에 놓이는 반투명 레이어
- 재료 이미지 소켓: 기존 회색 오브젝트 14개 위에 가로 7개, 세로 2줄로 배치
- 재료 이미지: `assets/materials/material_01.png`부터 `material_14.png`까지 서로 다른 PNG8 파일 사용
- 재료통과 PNG소켓: 원근 변형 없이 동일한 크기의 직사각형과 정방형으로 표시
- 재료통 테두리: 안쪽 방향 2px, `#bfbfbf`
- 창 크기 변경 시 800 x 600 기준 비율을 유지하며 전체 화면이 확대/축소됨
- 플레이 영역 안의 Y 295~400에 마우스를 올리면 테이블과 재료통이 이징으로 10px 상승
- 호버 상태의 테이블을 클릭하면 약 3초 동안 플레이 Y 100까지 올라가 조리상태로 전환
- 조리상태에서 플레이 Y 0~`kCookingTableY`를 클릭하면 비조리상태로 복귀
- 조리상태에서 각 PNG소켓에 마우스를 올리면 해당 소켓만 105%로 이징 확대
- 테이블은 최대 이동 거리보다 15px 더 연장되어 상승할 때 하늘이 노출되지 않음
- 유리돔은 테이블 이동 그룹에 포함되어 항상 함께 이동
- 유리돔은 정적 배경과 분리된 반투명 흰색 박스로만 표시
- 테이블 테두리: 위쪽 4px, `#422910`; 좌우 15px 및 아래 5px 확장부는 화면 밖에 숨김
- 조리상태 도마: `#b6a18c`, 플레이 영역 `(120, 300)`, 크기 160 x 78
- 조리상태에서 PNG소켓을 클릭하면 해당 재료가 도마 안의 무작위 위치에 복제됨
- 우측 하단 50 x 30의 `#94c293` 버튼은 복제 재료를 지우고 비조리상태로 복귀
- 복제 위치에는 임시 `#ffea00` 사각형이 표시되며 초기화 시 함께 삭제
- 초기화 버튼은 조리상태 진입 완료 후 부드럽게 페이드인
- 재료통들과 PNG소켓은 기존 위치보다 5px 아래에 배치
- 화면 명칭: 재료통들, PNG소켓, 테이블, 유리돔, 하늘, 배경
- NPC 주문 상태: 주문 전(입장 중), 주문 중(최초 주문 대사 중), 주문 끝남(최초 주문 이후)
- C++ 소스 인코딩: UTF-8 강제

## 빌드

Visual Studio의 **C++를 사용한 데스크톱 개발** 구성과 CMake가 필요합니다.

```powershell
cmake -S . -B build
cmake --build build --config Release
```

실행 파일은 일반적으로 `build/Release/OnePointFourFourMBGame.exe`에 생성됩니다.
방향키로 소실점을 움직일 수 있고 `Esc` 키로 종료할 수 있습니다.

기본 소실점을 코드에서 바꾸려면 `src/main.cpp`의
`kDefaultVanishingPointX`, `kDefaultVanishingPointY` 값을 수정하면 됩니다.
